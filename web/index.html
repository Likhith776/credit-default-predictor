ABOUT THE MODEL

One model.
Seven tables.
Every score explained.

Built on the Kaggle Home Credit Default Risk dataset — 307,511 labeled loan applications joined to bureau histories, previous applications, installments, and card balances. LightGBM turns 299 engineered features into a default probability; SHAP turns that probability into a reason.

01Relational feature engineering — 5 aggregators collapse 56M+ rows of monthly history into one row per applicant.
02Peer-rank and trend features capture where an applicant sits in their cohort and which way their DPD is moving.
03The same SHAP explainer ships to every surface — API, site, and the original Streamlit demo.

Applicant data in

Eight inputs — income, loan amount, annuity, employment, age, family, education, contract type. The same fields a loan officer would write down first.

02

Feature engineering

Unfilled fields take their training medians; domain ratios, peer ranks, and one-hot columns are computed — a 299-dimensional vector from 7 tables.

03

LightGBM scoring

A single gradient-boosted model — 263 trees, scale-pos-weighted for the 8% default rate — outputs a calibrated default probability.

04

SHAP explanation

The TreeExplainer decomposes this individual score into per-feature impacts: red pushed risk up, cyan pushed it down, for this applicant specifically.

Probability, tier, and the top factors — everything a human needs to agree or disagree with the model.

LIMITATIONS

What this is not.

This is a modeling and explainability portfolio piece, not a lending system. The risk thresholds are illustrative, not calibrated to a real cost function; no fairness or disparate-impact testing has been performed across protected attributes; and the peer-rank features reference the training population, so a real deployment would need periodic recalibration as the applicant pool shifts.
